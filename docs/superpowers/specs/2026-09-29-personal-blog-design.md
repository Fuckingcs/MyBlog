# 胡某人的个人博客设计

## 目标

建立一个可部署到 GitHub Pages 的个人博客。网站以灰白色、简洁而有内容的视觉风格呈现个人简介，文章分为「随感」和「笔记」。作者通过编辑 Markdown 文件发文，提交到 GitHub 后自动构建并发布。

## 页面与视觉

### 全站

- 站名为「胡某人的博客」，顶部导航包含「首页」「随感」「笔记」。
- 灰白配色，系统无衬线字体，清晰的文字层级，圆角卡片和轻微阴影。导航字号与正文层级协调。
- 桌面、平板、手机均可阅读；窄屏时导航和卡片布局自适应。
- 页面不依赖装饰性图片。没有文章图片时仍保持完整视觉效果。

### 首页

- 使用已选定的 D 版信息卡片布局，并与栏目页统一为灰白风格。
- 展示「胡某人」、北京科技大学计算机科学与技术专业、ENTP、对强化学习（RL）的兴趣，以及博客用于记录随感和学习笔记的简短说明。
- 「随感」和「笔记」为清晰可点击的入口。首页不展示文章列表。
- 简介文案集中放在一处，便于以后修改。

### 栏目页

- 「随感」与「笔记」各有独立页面，展示各自的文章，不混排。
- 页面标题与说明居中，字号比第一版草图大。
- 桌面端文章卡片每行四列、每页两行，最多八篇；平板两列、手机一列。
- 卡片使用灰白色、圆角和轻微阴影。上半部显示封面，下半部显示日期、标题与最多两行摘要，不显示篇数编号。
- 文章按发布日期从新到旧排列。超过八篇时分页；分页位于卡片区域下方的中央，控件字号和点击区域较大。
- 没有文章时显示简短的空状态，不填充虚构文章。

### 文章页

- 文章页显示标题、发布日期、所属栏目、正文及返回栏目入口。
- 正文采用适合阅读的行宽与行距，并为标题、引用、列表、代码块和图片提供统一样式。
- 文章图片保持比例，不溢出正文区域。

## 内容规则

- 文章由 Markdown 文件组成。每篇至少填写标题、发布日期和所属栏目（`随感` 或 `笔记`）。
- 卡片摘要自动从正文中的可读文字提取，去掉 Markdown 标记，并在页面上限制为两行。
- 卡片封面自动使用该文章正文中的第一张 Markdown 图片；同一图片仍保留在正文中。没有图片时显示灰白渐变。图片可以按文章归档放在站点的公共图片目录中。
- 网站不发布设计草图中的示例文章。首次上线没有正式文章时，两个栏目显示空状态。
- 提供一份简短的发文说明和文章模板，让作者能在 GitHub 网页上新增 Markdown 文件、填写必要信息、添加图片并提交。

## 技术与发布

- 使用 Astro 构建静态网站，用内容集合管理 Markdown 文章。
- GitHub Actions 在默认分支发生变更时构建并发布到 GitHub Pages。
- 部署配置须适配最终 GitHub 仓库地址；确定 GitHub 用户名和仓库名后填写站点 URL 与路径前缀。正式发布前由作者确认仓库。
- 本地开发可预览页面；提交前验证构建通过，并检查桌面和手机布局、栏目过滤、分页、摘要与首图规则。
- 文章元数据缺失或栏目值无效时构建应给出明确错误，避免错误内容悄悄上线。

## 范围

首版包含首页、两个栏目、文章页、分页、自动封面与摘要、响应式样式、发文说明和 GitHub Pages 部署配置。暂不包含评论、搜索、账号系统或网页写作后台。后续可以在实际使用时再决定是否增加。
